# Dependency and provenance review

MIT was selected for project-owned code because the reviewed declared dependencies use permissive MIT, ISC, BSD, Apache-2.0 and PSF licences. Their notices and conditions still apply; see THIRD_PARTY_NOTICES.md and docs/licenses. python-dateutil is dual Apache-2.0/BSD-3-Clause. There is no detected copyleft dependency in the reviewed installation.

The scheduling engine and interface were supplied by the project owner for this preparation. Source was selected by allowlist; no third-party connector, operational dataset, pre-existing screenshots, downloaded artwork or account-session material was imported. The simple calendar SVG is retained from supplied project source; no WhatsApp/Meta brand assets are shipped. Screenshots are newly captured using fictional fixtures. No original licence file or third-party source notice was present in the selected source. The repository owner must have the rights to grant MIT on that original code; dependency metadata cannot independently establish original authorship or substitute for that confirmation before publication.

The original Python framework dependency resolved to a Starlette version with reported advisories. The public copy updates FastAPI/Starlette/Uvicorn; final audit results are recorded in VERIFICATION.md. npm audit and pip-audit provide a dated vulnerability snapshot, not a permanent guarantee. Image operating-system packages are separate from these package-manager audits and were not exhaustively audited by an image CVE scanner.

Top-level Python requirements are exact-pinned; the runtime inventory records resolved transitive versions, which are also pinned in requirements.txt. JavaScript dependencies use package-lock.json. Docker base-image tags remain updateable; review and rebuild images regularly. A runnable GitHub Actions workflow and Dependabot configuration are included, with no publishing permissions or deployment steps. GitHub-hosted execution remains pending until a repository exists.
