# Security policy

Only the 0.1.x demo release is in scope for current maintenance. There is no real sending provider.

Do not post secrets, personal messages, session cookies or sensitive reproduction data in public issues. When the GitHub repository is created and private vulnerability reporting is enabled, use its Security → Report a vulnerability workflow. Until that channel exists, arrange a private reporting channel with the repository owner before sharing sensitive details. No monitored security email or response-time guarantee is claimed.

Include affected version, impact and minimal fictional reproduction steps. See docs/SECURITY-GUIDE.md for deployment controls and limitations. Disclosure of a credential should trigger revocation/rotation outside this repository; deleting a file or rewriting Git history alone does not revoke it.
